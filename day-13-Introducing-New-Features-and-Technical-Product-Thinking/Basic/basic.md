
# Prioritisation Frameworks: RICE, MoSCoW, and Impact vs. Effort

Prioritisation frameworks help product teams decide which features, improvements, and tasks should be completed first.

Since time, budget, and resources are limited, these frameworks help teams focus on the work that provides the most value.

There are three commonly used prioritisation frameworks:

## 1. RICE Framework

### What Is RICE?

RICE is a prioritisation framework that evaluates feature ideas using four factors:

- **Reach:** How many users will be affected by the feature?
- **Impact:** How much value will the feature provide?
- **Confidence:** How confident is the team in its estimates?
- **Effort:** How much work is required to implement it?

### RICE Formula

RICE Score = (Reach × Impact × Confidence) / Effort

A higher RICE score means a feature offers greater expected value relative to its required effort.

### Example

| Factor | Feature A | Feature B | Feature C |
|---|---:|---:|---:|
| Reach | 5,000 | 2,000 | 1,000 |
| Impact | 2 | 3 | 1 |
| Confidence | 80% | 100% | 50% |
| Effort | 4 | 2 | 1 |
| **RICE Score** | **2,000** | **3,000** | **500** |

**Priority order:**

1. Feature B – 3,000
2. Feature A – 2,000
3. Feature C – 500

Feature B receives the highest priority because it has the highest expected value compared to its effort.

### When Is RICE Useful?

- Comparing multiple feature ideas.
- Prioritising product backlog items.
- Planning product roadmaps.
- Making data-driven prioritisation decisions.

## 2. MoSCoW Framework

### What Is MoSCoW?

MoSCoW is a prioritisation framework that categorises requirements based on their importance.

It is commonly used in Agile projects, project planning, and release management.

It consists of four categories:

**A. Must Have**

Essential requirements that must be completed for the product or release to work as expected.

Examples:
- User login.
- Payment processing.
- Data security.

**B. Should Have**

Important requirements that provide significant value but are not essential for the current release.

Examples:
- Email notifications.
- Order tracking.
- Transaction history.

**C. Could Have**

Optional improvements that provide additional value but have lower priority.

Examples:
- Dark mode.
- Additional customization options.
- Interface animations.

**D. Won't Have (For Now)**

Requirements that will not be included in the current release but may be considered later.

Examples:
- Advanced AI features.
- Additional language support.
- Complex reporting features.

### MoSCoW Example

| Requirement | Priority |
|---|---|
| User registration and login | Must Have |
| Payment processing | Must Have |
| Order tracking | Should Have |
| Email notifications | Should Have |
| Dark mode | Could Have |
| AI shopping assistant | Won't Have |

### When Is MoSCoW Useful?

- Defining project scope.
- Managing stakeholder expectations.
- Planning releases.
- Identifying essential requirements.
- Managing limited development resources.

**Important:** Not every requirement should be labelled Must Have. Otherwise, the framework loses its usefulness.

## 3. Impact vs. Effort Framework

### What Is Impact vs. Effort?

This framework compares the value of a task against the amount of work required to complete it.

It uses two factors:

- **Impact:** How much value will the task provide?
- **Effort:** How much time and resources will it require?

Tasks are divided into four categories.

### Impact vs. Effort Matrix

| Category | Description | Priority |
|---|---|---|
| **High Impact, Low Effort** | Significant value with little work. | Quick Wins – Prioritize |
| **High Impact, High Effort** | Significant value but requires substantial work. | Major Projects – Plan carefully |
| **Low Impact, Low Effort** | Small improvements requiring little work. | Fill-ins – Do when possible |
| **Low Impact, High Effort** | Little value despite considerable work. | Time Sinks – Deprioritize |

### Understanding the Four Categories

**A. Quick Wins**

Tasks that provide high value with minimal effort. These should generally be prioritised.

**B. Major Projects**

Tasks that provide high value but require significant resources and planning.

**C. Fill-ins**

Small improvements that provide limited value and can be completed when time is available.

**D. Time Sinks**

Tasks that require considerable effort but provide little value. These are generally deprioritised.

### When Is Impact vs. Effort Useful?

- Identifying quick wins.
- Prioritising sprint tasks.
- Comparing development effort against expected value.
- Avoiding unnecessary work.
- Making quick prioritisation decisions.

## 4. Comparing the Three Frameworks

| Framework | Main Focus | How It Works |
|---|---|---|
| **RICE** | Expected value versus effort | Calculates numerical scores. |
| **MoSCoW** | Requirement importance | Categorises requirements into four groups. |
| **Impact vs. Effort** | Value versus complexity | Places tasks into four quadrants. |

### When Should Each Framework Be Used?

- **RICE:** When comparing multiple features and determining which offers the greatest expected value.
- **MoSCoW:** When defining project scope and deciding which requirements are essential for a release.
- **Impact vs. Effort:** When quickly evaluating tasks and identifying high-value, low-effort improvements.

## 5. Using the Frameworks Together

These frameworks can be combined during product planning:

1. **MoSCoW:** Identify essential requirements for the release.
2. **RICE:** Rank feature ideas based on their expected value and effort.
3. **Impact vs. Effort:** Identify quick wins and tasks that require more planning.

Final decisions should also consider business goals, deadlines, dependencies, and technical risks.

**The main goal of prioritisation is to ensure that teams spend their time and resources on the work that delivers the greatest value.**
