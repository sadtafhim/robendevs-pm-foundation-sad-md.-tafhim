
# Design Briefs, UX Basics, Figma Basics, and Design Principles

# 1. Design Briefs: Explaining Users, Goals, Flows, and Constraints

## 1.1 What Is a Design Brief?

A design brief is a document that explains what needs to be designed, who will use it, what it should achieve, and what limitations the designer must consider. It gives designers the information they need before starting work and helps prevent misunderstandings or incorrect assumptions.

## 1.2 What Should a Design Brief Include?

A good design brief should cover four main areas.

### A. Users

Designers need to understand who will use the product and what those users need.Different user groups may have different requirements, expectations, and permissions.As a Business Analyst, you should clearly identify these groups so designers can create an interface that meets their needs.

### B. Goals

Goals explain what users should be able to accomplish through the application.Clearly defined goals help designers make better decisions about layout, navigation, and functionality.

### C. User Flows

User flows describe the steps users follow to complete a task.They help designers understand which screens are required, how users navigate between them, and what happens during alternative or unsuccessful scenarios.You should communicate both the main user journey and important exceptions, such as failed payments or incorrect information.

### D. Constraints

Constraints are limitations or requirements that designers must follow.

Common types include:

- **Technical:** The design must work with existing technology.
- **Business:** Features must follow company policies and business rules.
- **Platform:** The application must support required devices and screen sizes.
- **Accessibility:** The interface must support users with different abilities.
- **Time:** Designs must be completed within the agreed deadline.

Identifying constraints early helps prevent unnecessary redesign work.

## 1.3 Why Are Design Briefs Important?

Design briefs help keep designers and stakeholders aligned.

They help:
- Reduce misunderstandings.
- Keep designs aligned with business requirements.
- Identify missing information.
- Prevent incorrect assumptions.
- Reduce unnecessary revisions.

As a Business Analyst or Project Manager, your responsibility is to communicate user needs, business goals, expected functionality, and project constraints.

# 2. UX Basics: User Flows, Wireframes, High-Fidelity Designs, and Prototypes

## 2.1 What Is UX?

UX stands for User Experience. It refers to the overall experience users have when interacting with an application, website, or product.Good UX means users can understand the application, navigate it easily, and complete tasks without unnecessary confusion.UX isn't just about appearance. It's about making sure the product works well from the user's perspective.

## 2.2 User Flows

A user flow is a visual representation of the steps users follow to complete a task.

User flows help identify:

- Required screens.
- Navigation between screens.
- Available user actions.
- Alternative paths.
- Error scenarios.

As a Business Analyst, you should review user flows to ensure all important scenarios are covered.

## 2.3 Wireframes

A wireframe is a basic layout of an application screen. It shows where elements should appear without focusing on colors, graphics, or detailed styling. Think of it as the skeleton of an interface.

Wireframes focus on:

- **Layout:** Where elements are positioned.
- **Structure:** How the screen is organized.
- **Navigation:** How users move between screens.
- **Content:** Where text, images, and buttons appear.

Wireframes help teams review screen structures before investing time in detailed designs.

## 2.4 High-Fidelity Designs

A high-fidelity design is a detailed visual representation of what the final application should look like.

It includes:

- Colors and backgrounds.
- Typography and font sizes.
- Buttons and input fields.
- Icons and images.
- Spacing and alignment.
- Borders and shadows.

High-fidelity designs help stakeholders review the interface and give developers a clear visual reference for implementation.

**Main difference:** Wireframes focus on structure, while high-fidelity designs focus on the complete visual appearance.

## 2.5 Prototypes

A prototype is an interactive version of a design that demonstrates how the application is expected to work.Users can interact with screens, click buttons, and navigate through different parts of the application.

Prototypes help teams:

- Test navigation and interactions.
- Identify usability problems.
- Collect stakeholder feedback.
- Review user journeys.
- Understand expected functionality.

A prototype usually doesn't have a working backend or actual business logic. It simulates interactions to demonstrate the intended experience.

## 2.6 How These Concepts Work Together

These concepts are commonly used throughout the design process:

1. **User Flows:** Define how users complete tasks.
2. **Wireframes:** Establish the structure of each screen.
3. **High-Fidelity Designs:** Add visual details and styling.
4. **Prototypes:** Connect screens and simulate interactions.

As a Business Analyst or Project Manager, you should review each stage to ensure the design matches the requirements and supports the intended user experience.

# 3. Figma Basics: Navigating Files, Leaving Comments, and Viewing Prototypes

## 3.1 What Is Figma?

Figma is a collaborative design tool used to create wireframes, user interfaces, prototypes, and design systems.It allows designers, developers, and other team members to work together and review designs in a shared workspace.You don't need to become a Figma expert, but you should know how to navigate files, inspect designs, leave comments, and view prototypes.

## 3.2 Navigating Figma Files

A Figma file usually contains different pages, frames, layers, and design elements.

### A. Pages

Pages organize different sections of a project within one Figma file.They help designers separate different parts of an application.

### B. Frames

A frame represents an individual screen or design area.Frames help organize individual screens within a design file.

### C. Layers

Layers are the individual elements that make up a design, including text, images, buttons, icons, and shapes.Designers use layers to organize and edit different parts of an interface.

### D. Properties Panel

The properties panel displays information about a selected design element.

Depending on your access, you may be able to inspect:

- Width and height.
- Position and spacing.
- Colors.
- Typography.
- Borders and alignment.

This information helps you understand design specifications and communicate them to developers.

## 3.3 Leaving Comments in Figma

Figma allows team members to leave comments directly on designs. This makes feedback easier to understand because comments can be attached to specific screens or elements.

A useful comment should:

1. Identify the issue.
2. Explain why it matters.
3. Describe the expected change.

Use comments to ask questions, clarify requirements, and communicate design changes.

## 3.4 Viewing Prototypes in Figma

Figma allows designers to share interactive prototypes so stakeholders can review the expected user experience.You can interact with a prototype without modifying the original design.

When reviewing a prototype, check:

- Whether all required screens are connected.
- Whether buttons lead to the correct screens.
- Whether navigation is logical.
- Whether important actions provide feedback.
- Whether error and empty states are included.

Remember that a prototype demonstrates intended behavior. It doesn't mean the actual functionality has been developed.

## 3.5 Why Should Business Analysts and Project Managers Know Figma?

Understanding Figma helps you work more effectively with designers and developers.

You should be able to:

- Review designs against requirements.
- Identify missing screens and interactions.
- Leave clear feedback.
- Understand user navigation.
- Help developers understand the expected interface.
- Track design changes and discussions.

You don't need to create professional designs. You just need to understand how to navigate and review them.

# 4. Design Principles: Consistency, Hierarchy, Feedback, and Accessibility

Design principles help create interfaces that are easy to understand, navigate, and use. As a Business Analyst or Project Manager, understanding these principles helps you evaluate the quality of a design.

## 4.1 Consistency

Consistency means using similar design patterns and behaviors throughout an application. Users shouldn't have to learn a different way of interacting with every screen.

Examples include:

- Similar buttons should have consistent styling.
- Navigation menus should behave similarly across pages.
- Fonts and colors should follow the same design system.
- Input fields should have consistent layouts.
- Icons should have recognizable meanings.

Consistency makes applications easier to learn, reduces confusion, and creates a familiar user experience. As a Business Analyst, check whether similar features follow the same design and behavior across the application.

## 4.2 Visual Hierarchy

Visual hierarchy is the arrangement of elements according to their importance. It helps users identify important information and understand what actions they should take.

Designers create visual hierarchy using:

- **Size:** Important headings are usually larger.
- **Color:** Important buttons and messages may use noticeable colors.
- **Spacing:** Separates sections and improves readability.
- **Position:** Places important information where users can easily find it.
- **Typography:** Uses font size and weight to distinguish content.

Visual hierarchy helps users find information quickly and understand the structure of a page. As a Business Analyst, check whether important information and actions are clearly visible.

## 4.3 Feedback

Feedback is how an application communicates the result of a user's action. Users should receive a clear response whenever they interact with the interface.

Common types of feedback include:

- Loading indicators.
- Success messages.
- Error messages.
- Confirmation screens.
- Updated interface elements.

Good feedback should:

- Appear at the right time.
- Clearly explain what happened.
- Explain what users should do next when necessary.
- Cover successful and unsuccessful actions.

As a Business Analyst, define the expected behavior after important actions, including loading states, success messages, errors, and confirmations.

## 4.4 Accessibility

Accessibility means designing applications so people with different abilities can use them effectively. This includes people with visual, hearing, motor, and cognitive disabilities.

Important accessibility considerations include:

### A. Color Contrast

Text should have sufficient contrast against its background to remain readable.

### B. Keyboard Navigation

Users should be able to navigate important parts of an application using a keyboard rather than relying entirely on a mouse or touchscreen.

### C. Screen Reader Support

Screen readers help visually impaired users understand and navigate interfaces. Buttons, forms, and images should have meaningful labels and accessible information.

### D. Readable Typography

Text should be appropriately sized and clearly organized.

### E. Clear Error Messages

Error messages should explain what went wrong and how users can fix it. Accessibility removes barriers for users with disabilities and improves usability for everyone. As a Business Analyst or Project Manager, include accessibility requirements from the beginning of the project. For web applications, WCAG (Web Content Accessibility Guidelines) provides widely recognized accessibility standards.

# 5. How These Concepts Work Together in a Real Project

Consider a client who wants to build an e-commerce application.

Here's how these concepts fit into the project:

1. **Create the Design Brief**

   Explain the target users, business goals, expected user journeys, and project constraints.

2. **Define the UX**

   Identify user flows, create wireframes, prepare high-fidelity designs, and build prototypes.

3. **Review Designs in Figma**

   Open shared design files, inspect screens, leave comments, and test prototypes.

4. **Evaluate Design Principles**

   Check consistency, visual hierarchy, feedback, and accessibility.

5. **Hand Off Designs to Developers**

   Make sure developers understand the approved screens, interactions, and requirements before implementation.
